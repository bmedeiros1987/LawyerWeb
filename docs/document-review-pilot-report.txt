Implemented:
- Desktop-only route /app/documentos/revisao-piloto linked from Documents. Requires existing authenticated workspace membership + documents.edit. API reuses desktop JSON same-origin and existing permission guards; no new auth or credentials.
- One interface with read-only fictitious document, represented party and objective, clause selection, question/conversation, exact-anchor proposal, accept/reject, explicit conflicts, simulated opinion and confirmed local immutable review snapshot.
- Three actual generated contracts: services DOCX, rental PDF, confidentiality DOCX. Browser checks original file bytes SHA-256 before starting. Text preview comes from fixture manifest; a separate test verifies it exactly matches generated DOCX XML/PDF text. This is NOT arbitrary DOCX/PDF parsing.
- Original is never written. Accepted proposal replaces only exact text at its current hash-bound offsets; old pending anchors become conflicts. Rejected proposals do not change text. Pending/conflicted proposals block save until explicitly resolved/discarded.
- Snapshot contains real hashes of original bytes, text, decisions and simulated opinion. JSON snapshots are exclusively created, read-only by normal mode bits, and scoped by user+workspace+review ID. Parent snapshots are checked. App refuses overwrites and links; immutability is app-enforced, NOT OS/WORM protection against outside processes or the account owner.
- Saving writes/fsyncs the snapshot file and, on POSIX, its directory. This is not a fully tested crash-durability guarantee (new ancestor directories/controller behavior/Windows remain unproven).
- Provider endpoint is narrow, disabled and has no network implementation, account discovery, credential loading, tools or fallback model. It returns provider-disconnected/503 even with consent. Contract text is inert data, rendered as text, never authorization for tools/shell.
- Opening arbitrary client files and connecting ChatGPT are visibly blocked. Consent covers local simulation and save only. No document or context sent externally.

What is NOT implemented/verified:
- No real AI/legal review. Replies/proposals are deterministic fixture demonstrations. No citations, jurisprudence, legal adequacy or substantive recommendations are verified.
- No WYSIWYG DOCX editor or DOCX roundtrip/export; saved artifact is a JSON review snapshot, not a new Word file preserving original formatting.
- PDF original may be viewed inline by the browser reader, read-only. PDF.js rendering/text-layer selection is NOT integrated. Anchors are exact fixture text offsets/clause IDs, not validated PDF page/geometry coordinates.
- Only clause 2 has a predefined sample proposal. Other clauses can be selected/read, but no proposal is fabricated for them.
- No reopening/listing history after restarting. Current session shows saved snapshots. Existing desktop backup/restore does NOT include review-pilot snapshots; therefore not ready for persistent real client data.
- Existing PR60 concurrency findings remain a release prerequisite; earlier patch is available separately and must be reviewed/integrated without a conflicting push.
- No real database, clients, Drive documents, email, WhatsApp, Telegram, user accounts or secrets accessed. No Windows execution. No new subscriptions/costs, persistent connections or account authentication.
